# SEED_AND_DATA_ALIGNMENT.md — which results sit on which simulated datasets (2026-07-28)

One place to answer: *for a given pair of learners at a given sample size, were
they computed on the same simulated data — and if not, what breaks?*

Written after a 2026-07-28 audit that found the production docs at n=1200 were
wrong on this exact question for two years' worth of archived rows (see
[§6](#6-provenance-of-this-document)). Every claim below is either read off the
code or backed by a re-runnable numeric check.

---

## 1. Three axes, not one

The single most common error in this project's documentation has been collapsing
these into one statement. They are independent, and they break different things.

1. **Data alignment** — do rows labelled `sim_id = k` refer to the *same
   realized dataset*? This is the one that matters for any paired analysis.
   Binary: either the two cohorts share the `sim_id`→dataset map or they don't.
2. **Fold alignment** — given the same data, do the cross-fit arms use the same
   *partition*? Misalignment here does **not** bias anything; it means the two
   cohorts' CF noise is independent rather than shared, so paired CF contrasts
   are noisier than they look.
3. **Reproducibility** — can the rows be regenerated bit-for-bit? Affects
   auditability only. A row can be perfectly aligned on data and folds and still
   be irreproducible (unseeded run, forked-worker RNG, drifting cloud endpoint).

A cohort can pass 1 and fail 2 and 3 (the n=1200 v3 CF imports), or pass 1 and 2
and fail 3 (n=1200 unseeded NoCF), or fail all three (the Python TabPFN tracks
vs the R learners).

## 2. The canonical convention

Every R pipeline, at every sample size, uses:

- **Datasets**: `_data_inputs/sim_XXXX.rds`, generated by `set.seed(sim_seed)`
  with `sim_seed = starting_seed + sim_id` and `starting_seed = 1`.
  So **sims 1…200 ↔ seeds 2…201**.
- **CF folds**: `generate_folds(n, K, seed = sim_seed*1000 + 7)` — learner-
  independent, so every R learner shares one partition per sim.
- **No-CF fits**: `set.seed(sim_seed*1000 + 11)` — *at n=1200 this landed only
  2026-07-28, so all archived n=1200 NoCF rows predate it* (see §4).
- **K**: 10 at n=200, 5 at n=1200 and n=5000 (`folds_by_n`).

The Python TabPFN notebooks at n=1200/n=5000 use a *different* convention:
`numpy.random.RandomState(seed)` with **`seed = sim_id`** (not `sim_id + 1`),
cached to `_data_inputs/n<k>/sim_XXXX.csv`. Same DGP, different draws.

> **Never join across tracks on the `seed` column.** The Python tracks label
> `seed = sim_id`, the R tracks label `seed = sim_id + 1`. Join on `sim_id`.
> At n=200 the *data* are shared but the *label* is still off by one.

### The short version

- **n=200 — fully aligned.** Single-source provenance; every learner, R and
  Python alike, is on the same datasets. The only caveat is fold partitions for
  the TabPFN CF arm.
- **n=1200 — aligned on data for every R-track learner** (including both v3
  import archives), **not aligned for the five Python-track learners.** Fold
  conventions are mixed, and the NoCF arm is unseeded.
- **n=5000 — aligned for all R learners, not aligned for the three TabPFN
  learners.**

## 4. n=1200 seeding gap — FIXED 2026-07-28

`Naimi_streamlined.v4/analysis/modules/nuisance.R` had **no `set.seed()` on the
no-cross-fit path** while both siblings did (`Naimi_v4.n200` :57, `..._n5000`
:62); `DEVIATIONS.md` D1 described it as a property of *historical* runs, but
the code had never been fixed. **The one-line port landed 2026-07-28** (§9.1):
`set.seed(sim_seed * 1000 + 11)` on the NoCF path, matching the siblings.
Future n=1200 NoCF runs are reproducible; the archived NoCF rows remain
unseeded draws (nothing about them changed, and nothing can).

## 5. When misalignment is a problem — and when it isn't

### ❌ Broken by DATA misalignment (axis 1)

- Per-sim paired learner-vs-learner contrasts and their sign tests.
- **Paired Monte-Carlo SE** — `naimi_figures_helpers.R` `tie_mode="paired"`
  computes `sd(per-sim difference)/sqrt(k)` keyed on `sim_id`. Across misaligned
  cohorts this silently loses the shared-draw correlation: the windows are wrong,
  so tie/tier assignments in ranking panels are unreliable.
- Within-learner CF-vs-NoCF deltas where the two arms come from different cohorts.
- Joining any learner to the per-sim **oracle** rows (use `oracle_python` for the
  Python tracks — that is exactly why it exists).
- Balance-vs-bias scatters that put a per-unit-π̂ quantity on x and a per-sim
  bias on y.
- Common-random-numbers variance reduction; debugging "what happened on sim N".

### ✅ Unaffected by DATA misalignment

- Aggregate bias, RMSE, coverage, empirical SE over the 200 sims — all cohorts
  draw from the identical DGP, so misalignment is pure Monte-Carlo relabeling,
  not bias.
- Learner rankings and heatmaps built from those aggregates.
- Unpaired (independent) Monte-Carlo SEs and their CIs.
- Every dashboard and summary table that aggregates to a per-(learner, scenario,
  arm) mean *before* comparing — which is all of them.

### ⚠️ Degraded, not invalidated, by FOLD misalignment (axis 2)

- Paired CF contrasts remain **unbiased** but carry independent fold noise, so
  they are wider than a same-fold comparison. Affects the n=1200 v3-CF-imported
  cells and every TabPFN CF arm at all three n.

### 🔍 Affected only by REPRODUCIBILITY (axis 3)

- Auditing, re-running, and bit-level validation. No statistical claim depends on
  it. Applies to: all n=1200 NoCF rows for stochastic learners, all
  `hal_discrete` CF rows (mclapply worker seeding), and every cloud TabPFN row
  (server-side drift across weeks).

## 7. The k=50 balance side-cars (n=1200 only)

`_data_processed/perunit/<learner>/<scenario>_<cf>/sim_XXXX.rds`, sims 1–50, 11
fitted learners × 4 arms (`hal_discrete/simple_cf` absent) + oracle / oracle_untrunc
/ unweighted references.

- **Data: fully aligned.** Every learner reads the `.rds` cache; the TabPFN arm
  reads `_data_processed/balance_v3_datasets/*.csv`, exported from those same
  `.rds` by `export_rds_for_v3_balance.R` *specifically* to avoid the numpy cache.
  Side-cars store the canonical seed (sim 1 → seed 2).
- **Folds:** the TabPFN balance arm uses `KFold(5, shuffle, random_state=sim_id)`,
  not the R partition. `ranger` and `sl_naimi_v2` use a propensity-only CF
  supplement (`balance_cf_supplement.R`).
- **These are RE-FITS, not the archived production nuisances.** They are produced
  by the current seeded code path, whereas the production n=1200 NoCF rows were
  unseeded and many CF rows are v3 imports. So balance ASMDs are internally
  consistent with `ipw_by_cell.csv` and with each other — **not** with the 200-sim
  estimator tables. Do not describe a balance number and an estimator number from
  those two sources as coming from the same fit.
- **2026-07-28 update:** two k=200 TabPFN side-car families converted from the
  SAVED fits now sit beside this study (§9.2 — done): `tabpfn_api_v3` at n=200
  (r_cache island, same-fits vs the production tables) and
  `tabpfn_api_v3_regen` at n=1200 (numpy island, same-fits vs the regen
  tables; aggregate-only against everything in this section). Balance runs:
  `Naimi_v4.n200/results/balance_20260728/` and
  `Naimi_streamlined.v4/results/balance_regen_k200_20260728/` (see their READMEs).
- No balance study exists at n=5000. (n=200 got one 2026-07-28, above.)

## 8. `tabpfn_api_v3_regen` (n=1200 and n=5000) — where it sits

Fresh v3 cloud fits generated 2026-07-25/26 because the endpoint drifts
server-side, making the May-2026 production rows unreproducible. Two learners
came out of it: `tabpfn_api_v3_regen` (the four Python estimators) and
`tabpfn_v3_api_tmleR` (R `tmle::tmle()` on the same fits).

**Alignment — identical to the track it regenerates, by deliberate choice:**

- Runs on the **numpy** cache (`_data_inputs/n{1200,5000}/*.csv`), because
  switching to the R datasets would have conflated a data-draw change with the
  cloud-drift measurement it was built to make.
- ❌ **Not** per-sim paired with any R-track learner or with `oracle` /
  `oracle_notrunc`. Aggregate comparisons only.
- ✅ Per-sim paired with `tabpfn_api_v3` (production), `tabpfn_api_v3_regen`,
  `tabpfn_v3_api_tmleR`, `oracle_python`, `oracle_notrunc_python` — these five
  form a **self-consistent Python-track island** on the numpy datasets.
- The R-sounding name `tabpfn_v3_api_tmleR` is a trap: it fixes the *fluctuation-
  algorithm* half of the cross-track caveat, not the *different-data* half.
- ⚠️ At n=200 the situation is the opposite — there the raw fits are on the
  R-exported data, so `tabpfn_v3_api_tmleR` **is** fully paired with the R learners.

**What the saved raw fits contain** (`results/tabpfn_api_v3_regen_outputs/v3api_raw_fits_n<k>.csv`):
`sim_id, scenario, cross_fit, seed, obs, Y, A, pihat_raw, mu0hat, mu1hat` —
per-unit, **pre-truncation**, complete at 800 cells × n obs (n=1200: 960,000 rows,
97 MB; n=5000: 390 MB). `obs` joins positionally to the numpy CSV, which carries
`C1–C4` and `Z1–Z4`. Verified 2026-07-28: `Y` matches the numpy cache to 2.8e-14
and `A` exactly.

**Consequence:** these fits are sufficient to compute **balance ASMDs over all
200 sims with zero API calls** — both ASMD targets (`modeling` and `true_C`) are
available, any truncation rule replays from `pihat_raw`, and the oracle/unweighted
references recompute exactly from `C` via `generate_propensity()`. The result
would be a 200-sim TabPFN balance curve **on the numpy datasets** — internally
paired with the Python-track island, aggregate-only against the k=50 R-cache
balance study in §7. See §9.2.

### 9.5 Re-audit paired-mode consumers now that n=1200 is known-aligned

`ISSUES_AND_IMPROVEMENTS.md` §6 flagged `naimi_figures_helpers.R`
`tie_mode="paired"` as unreliable for n=1200 CF panels, on two premises: the
backfill off-by-one (**remediated 2026-07-05**) and the v3 imports being on
different data (**refuted 2026-07-28**, §6). Both premises are now gone, so
paired mode at n=1200 is likely *more* valid than currently documented — only
fold-convention mixing remains, which widens the paired MC-SE rather than
invalidating it. Re-check the tie/tier assignments before relying on that note.

### 9.6 Add an alignment-group column to the canonical per-sim files

Defensive, cheap. Stamp each row with its island (`r_cache` / `numpy_n<k>` /
`r_cache_v3folds`) so paired-contrast code can *refuse* to pair across islands
instead of relying on a reader having found this document. The paired-ties
machinery already supports a cross-group fallback to independent MC-SE.

### 9.7 Unify the n=1200 fold conventions (optional, expensive)
